## 2. 背景与问题

### 2.1 业务背景

房租核算系统的数据可见范围，依赖用户在「权限管理 > 添加/编辑用户」中勾选的**主体类型**。主体类型包括集团、励步、考满分、投资系列，以及外包权限1–8等。

外包同学可见的法律主体范围，当前由财务老师走流程整理 Excel 清单，再由研发将公司 ID 写入登录代码白名单。

### 2.2 当前系统实现

| 对象 | 现状 | 问题 |
|---|---|---|
| 法律主体 `companies.main_body` | 页面单选，一个主体只能挂一个主体类型 | 无法表达「既是集团，又是外包权限1」 |
| 用户权限 `auth_admins.main_body` | 已支持多选 | 用户侧可多选，主体侧仍为单值 |
| 外包权限1–8（编码 37–44） | 登录时在 `auth_admin.php`、`LoginService.php` **硬编码公司 ID 白名单** | 名单变更依赖研发改代码、发版 |
| 法律主体配置管理 | 仅支持单条增删改，无导入 | 大批量调整依赖线下 Excel + 研发 |
| 离线清单 | `外包权限主体清单YYYYMMDD.xlsx` | 是流程凭证，不是系统配置源 |

### 2.3 痛点

1. **主痛点：发版窗口导致无法实时维护，影响外包录合同。** 外包权限名单增减本属业务配置，却依赖研发改硬编码并走发版；发版有窗口期（每周仅两天可发），名单无法即时生效。外包同学因此迟迟看不到对应法律主体，合同录入时效受影响，结账期尤为明显。
2. 一个主体无法同时归属多个主体类型，业务上「集团可见 + 外包可见」只能靠硬编码白名单叠加实现。
3. Excel 清单、代码白名单、页面主体类型可能不一致，排查成本高。
4. 财务老师无法在系统内按需维护、批量导入，只能走线下流程等研发发版。

### 2.4 本期目标

将「主体 ↔ 主体类型」关系做成系统可维护配置，并完成历史数据初始化，使外包权限名单不再依赖代码硬编码。

**业务语义**

- 同一个法律主体可同时挂多个主体类型标签。
- 用户按自己勾选的主体类型取并集可见：勾「集团」可见带集团标签的主体；勾「外包权限1」可见带外包权限1标签的主体；互不影响。

**上线要求**

- 初始化历史数据：将现有硬编码外包白名单 + 现有 `companies.main_body` 单值，迁移为「一个主体可挂多个主体类型」的关系数据。
- 验证通过后下线登录代码中的硬编码白名单。

### 2.5 功能入口

改造现有**法律主体配置管理**页，不新增独立外包权限维护页：

- 主体类型由单选改为多选；
- 支持单条维护、批量导入、全量导出；
- 列表展示一个主体挂载的多个类型。

## 4. 导入模板与校验

导入模板：`需求/主体类型导入模板.xlsx`

### 4.1 模板字段

| 列 | 字段 | 是否必填 | 说明 |
|---|---|---|---|
| A | 主体编码 | 是 | 系统法律主体编码，如 `TAL31`、`L301673` |
| B | 主体名称 | 否 | 仅人工核对；与系统不一致时以编码为准，结果中提示「名称不一致」 |
| C | 主体类型 | 是 | 单个或多个；多个用**英文逗号**分隔，如 `集团,外包权限1` |
| D | 本次调整内容 | 是 | 仅允许 `新增主体类型` / `删除主体类型`；模板中为下拉单选，不可手填其他值 |

模板结构：

| Sheet | 内容 |
|---|---|
| 主体类型导入 | 填写区；D 列下拉仅可选「新增主体类型」「删除主体类型」 |
| 主体类型枚举 | 主体类型枚举清单，供填写 C 列时对照 |

可选主体类型（与现网字典一致）：

`集团`、`励步`、`顺顺`、`考满分`、`投资A`、`投资B`、`投资C`、`投资D`、`投资E`、`投资F`、`哒哒`、`外包权限1`～`外包权限8`

### 4.2 换类型填法

不提供单独的「调整」枚举。主体从外包权限1调整到外包权限2时，填两行：

| 主体编码 | 主体名称 | 主体类型 | 本次调整内容 |
|---|---|---|---|
| A001 | 主体A | 外包权限1 | 删除主体类型 |
| A001 | 主体A | 外包权限2 | 新增主体类型 |

若主体 A 原为 `集团,外包权限1`，导入后变为 `集团,外包权限2`（集团保留）。

### 4.3 文件级校验

| 规则 | 失败处理 |
|---|---|
| 仅支持 `.xlsx` / `.xls` | 阻断导入，提示文件格式不正确 |
| 单次最多 2000 行（不含表头） | 阻断导入，提示拆分后重导 |
| 表头必须为：主体编码、主体名称、主体类型、本次调整内容 | 阻断导入，提示下载标准模板 |
| 无有效数据行 | 阻断导入，提示文件无数据 |

### 4.4 行级校验

| 规则 | 失败处理 |
|---|---|
| 主体编码为空 | 该行失败：主体编码不能为空 |
| 主体编码在系统中不存在 | 该行失败：主体编码不存在 |
| 主体类型为空 | 该行失败：主体类型不能为空 |
| 主体类型含非法值（不在字典内） | 该行失败：列出非法类型名 |
| 同一格内类型重复（如 `外包权限1,外包权限1`） | 自动去重后继续，结果记「已去重」 |
| 本次调整内容为空或不属于「新增主体类型/删除主体类型」 | 该行失败：本次调整内容仅支持新增主体类型或删除主体类型 |
| 本次调整内容=新增主体类型，且主体已有该类型 | 该类型跳过，记「已存在，跳过」；同行其他类型仍处理 |
| 本次调整内容=删除主体类型，且主体当前没有该类型 | 该类型跳过，记「本无此类型，跳过」 |
| 本次调整内容=删除主体类型后，主体将无任何主体类型 | 该行失败：不允许删空，至少保留一个主体类型 |
| 文件内同一主体编码多行 | 按行序依次执行；先删后增可完成类型调整 |
| 主体名称与系统不一致 | 不阻断；以编码为准，结果提示名称不一致 |

### 4.5 处理规则

- **新增主体类型**：只给主体追加指定类型，不覆盖、不清空其他类型。
- **删除主体类型**：只去掉指定类型，不删除法律主体本身。
- 一行可写多个类型：按类型逐个执行。
- 部分行失败不影响其他行成功提交（成功行落库，失败行回传原因）。
- 导入完成后展示：成功行数、失败行数、跳过项数；支持下载失败明细。
- 生效时机：`[待确认]` 建议导入成功后对新登录立即生效；已登录用户需重新登录后刷新可见范围。

### 4.6 导入结果示例

```text
导入完成
成功：2 行
失败：1 行
跳过：1 项（已存在）

失败明细：
第5行 | ZW99 | 外包权限3 | 删除主体类型 | 主体编码不存在
```
